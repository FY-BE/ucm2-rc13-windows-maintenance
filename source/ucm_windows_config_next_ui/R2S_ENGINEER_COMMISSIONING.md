# UCM2-R2S Windows 工程联调清单

本程序通过 WinUSB revision 9 与 ARM `ucm-runtime` 通信。ARM 自主模式下可读取状态、结果、波形和日志；配置、启停、维护及升级须先由设备确认切换到 `HOST_MANAGED`。Windows 不直接控制 PL 寄存器或驱动，也不计算正式力值。

## 上板前

1. 核对实体型号与物理接线。A001 与 DE168 的几何和最终力值验收分别记录。
2. 核对板卡启动后的 PL、驱动、ARM、配置身份及安全状态。Windows 连接成功或显示工程师登录，不等于这些检查通过。
3. 升级或带能量操作前，确认设备已安全停止，TX/HV 实际关断。物理输出档位按现场批准的级别分别测试。

## 常规操作

- 自主模式由 ARM 自行训练、采集并按 50 Hz 计算；Windows 显示 ARM 发布的结果。开模无载时正式力值可能无效，这不等同于 USB 故障。
- 进入托管模式时，等待 ARM 完成安全停止和控制权回执，然后再提交配置或启停。USB 租约失效后，ARM 安全停止成功才重新训练并回到自主模式；否则保持 `FAULT_SAFE`。
- 配置的 Apply 与 SaveStartup 是两个独立操作。以 ARM 最终回执和重新读取为准。
- 日志目录与分块读取使用 ARM 发布的原生 `.url3` 文件；本机下载完成后核对文件身份与 SHA256。

## R2S 升级

选择 `.u2p` 包，填写包内版本、型号及目标 Build ID。程序会从当前连接的 ARM 读取活动 Build ID，并在传输前校验 `U2P1` 包头、所需当前 Build ID、八个文件的顺序/权限/SHA256 和系统身份。旧 `UAP1` 包不进入 R2S 升级路径。

“传输并暂存”只完成接收、校验和写入非活动槽；激活必须单独确认。激活后重新连接并核对设备报告的活动槽、Build ID 与完整性。Windows 的本地预检不代替 ARM 对真实板卡的最终验收。若状态未知，先查询原事务，不盲目重发激活。

## 验收记录

保存 USB 枚举与协商、控制权切换、配置回执、结果/波形/日志、拔线恢复、升级暂存/激活/回滚及冷启动身份的原始记录。离线测试和便携包启动仅证明对应软件层级；真板 G7/G8/G9 必须分别留有设备端证据。
